`run.py` 决定这一题怎么走：多轮对话、角色、本地工具、把产物写到声明路径。

| 你负责 | 不要做 |
| --- | --- |
| loop、角色、handoff、本地 Tool | 最终 PASS、宿主凭据、自己提隔离 |
| 经 SDK `session` / `invoke` | 把某家私有 SDK 当 Core |

分数由 `evaluator.py` 给出：确定性脚本比对参考答案，或参考答案就位后的可选 LLM-as-judge。

<Callout type="idea" title="让 agent 代写">

```bash
npx skills add ZJU-REAL/ageval --skill ageval-sdk-harness
```

说清 loop 要怎么走，让本机 coding agent 写 `run.py`；下面的片段就是它要满足的约定。

</Callout>

```python
from ageval_sdk import RunContext, RunTerminal

async def run(ctx: RunContext) -> RunTerminal:
    async with ctx.agent.session("solver", max_turns=1) as session:
        reply = await session.invoke(ctx.params["instruction"])
    ctx.publish_json("reply", {"ok": bool(reply.get("ok")), "text": reply.get("text") or ""})
    if not reply.get("ok"):
        return RunTerminal.failed(str(reply.get("error") or "invoke_failed"))
    return RunTerminal.completed("ok")
```

`session.invoke` 可传 `tools` 与 `messages`。`openai-http` / `anthropic-http` 返回结构化 `tool_calls`；ACP 忽略工具目录，仍走文本 invoke。省略这两项就是 prompt-only。

`openai-http` 可在 profile 里设置 `options.stream: true`，为 Chat Completions 与 Responses 打开原生 SSE。任务拿到的 `invoke` 结果契约不变；流式只改变传输和进度证据，不改变任务契约或 PASS。流失败或未完整结束时是 `ok: false`。
实时活动会暂存未结束的词和凭证前缀，完成安全脱敏后继续显示文本，无需等待整个回答结束。
