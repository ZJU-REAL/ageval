## Hard boundaries

1. `run.py` completed **≠** PASS  
2. Trajectory / tokens / agent self-report **≠** score (including `evaluation/observation.jsonl`)  
3. PASS / FAIL comes only from the `evaluator.py` return value  
4. Suite / job aggregates (including pass@k) **≠** suite-level PASS authority  

## On the terminal

- **Result** — status and evaluation for this Attempt  
- **`logs`** — Attempt evidence locator under the Dataset root (e.g. `.ageval/runs/<run_id>`; typical when `k=1`)  
- Suite `pass_rate` / `mean_score` — observational  

## Always-k and pass@k / pass^k

After Always-k (`-k` / `--n-attempts`), suite `summary.json` → `metrics` includes:

| Key | Meaning |
| --- | --- |
| `pass_at_k` | pass@k (unbiased “≥1 success”; Harbor-style) |
| `pass_power_k` | pass^k (all-k success estimate) |
| `n_attempts` | Always-k budget for this job (CLI / job only — not `task.yaml`) |
| `k_values` | k list computed for this summary |
| `per_task` | Per-task `n` / `c` and per-k maps (audit) |
| Suite score | **Mean over tasks** for that metric (omit tasks with too few samples) |

### Contract: `metrics.pass_at_k` / `pass_power_k`

Each key is a **stringified k** (`"1"`, `"2"`, `"5"`, …). Value shape:

```json
{
  "1": { "value": 0.75, "n_tasks": 4, "incomplete_tasks": 0 },
  "2": { "value": 0.5,  "n_tasks": 3, "incomplete_tasks": 1 }
}
```

| Field | Meaning |
| --- | --- |
| `value` | Mean over tasks that can compute that k; `null` if none |
| `n_tasks` | Tasks included in that k’s denominator |
| `incomplete_tasks` | Tasks omitted (e.g. pass@k when `n < k`) |

**Upload / Registry:**

- `ageval results upload-suite` **ensures / recomputes** k metrics locally (from `attempts[]` or per-task `n`/`c`) before POST of the full `metrics` blob.
- Registry stores `metrics_json` as-is; list/get suite **does not strip** `pass_at_k` / `pass_power_k`.
- First-class columns remain `pass_rate` / `mean_score`; k metrics live under `metrics`.
- **Not** part of `config_fingerprint` / job identity; different k jobs may sit side by side.
- Legacy suites without k data: missing `metrics.pass_at_k` → Hub shows `—`.

**`task_refs` (multi-attempt):** may include `n`, `c`, `attempt_run_ids` (plus primary `run_id`) for audit and `--with-attempts`.

These are **observational aggregates**, not suite-level PASS.

## What Hub actually lists

| Upload command | Artifact | Hub primary UI |
| --- | --- | --- |
| `ageval results upload --run …` | Single Attempt | **Usually not** on Dataset Leaderboard / Task Jobs |
| `ageval results upload-suite --suite-run …` | Suite row + metrics / task_refs | **Leaderboard** only when complete and release-bound; incomplete or draft-bound rows stay on Task Jobs |
| `… --with-attempts` | Also packs attempt dirs | Jobs can open Attempt detail / trajectory |

So: to show a package run on the public board, use **suite run → upload-suite** against a published release, not attempt-only upload.

## Browse

[Viewer](../run/local-viewer.mdx).  
Attempt pages may show **Timing** (and **Tokens** when present). Trajectory steps follow file order (thought next to the tools it precedes). A step may show a duration when the sealed row has `elapsed_ms`. Time / tokens / step duration are **hints**, not PASS.

## Failure kinds

| Kind | Intuition |
| --- | --- |
| Config / lock | Never entered formal execution |
| Execution ERROR | Failed inside the boundary |
| FAIL | Evaluator says no |
| PASS | Evaluator says yes |

Exit codes: current CLI + skill `ageval-cli`.
